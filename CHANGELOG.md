# Changelog

## 2026-11-24 — 2.0.0

### Fixed
- The workflow file was not valid JSON (raw newlines and unescaped quotes inside `jsCode`) and could not
  be imported. It is now generated by `scripts/build-workflow.js` and checked by the tests.
- Funding was read from Kraken's absolute `fundingRate` field instead of `relativeFundingRate`, which
  overstated funding by orders of magnitude.
- Hourly funding was scaled to a day with ×3 (as if it were 8-hourly). The period is now measured from
  the data.
- One fee + slippage was subtracted from one day of funding. Costs are now a four-fill round trip compared
  against funding over a holding period.
- `Scenario Configs` was not connected to the flow, so its values were never used.
- The `profitable` flag ignored `minProfitDailyPct`; pass/fail now follows the documented policy.
- Repo layout now matches the README (`workflow/`, `docs/`, `.github/`).

### Changed
- Asset symbols use Kraken's linear `PF_` perps throughout (previously a mix of `PI_` and `PF_`).
- Cron interval 2 min → 15 min.
- The auto-scanner grid over fees, slippage and LTV is removed: it always picked the cheapest
  assumptions. It is replaced by three named cost scenarios, with alerts judged under `alertScenario`.
- Leverage by borrowing against the spot leg is removed; capital is split between spot and perp margin.
- Duplicate "HTTP Fallback" Telegram nodes (bot token in the URL) are removed.
- Google Sheets columns changed (see README).

### Added
- Persistence filter: 24h/7d means, sign stability, minimum history.
- Negative funding is flagged as `needs spot short` instead of being shown as a trade.
- Experimental strategies: Kraken–Hyperliquid perp-perp spread, dated-futures basis.
- `scripts/fetch-history.js`, `scripts/backtest.js`, and a dependency-free test suite.
- `legacy/dsfab-process3-2025-08.zip`: the previous release, archived as it was.
